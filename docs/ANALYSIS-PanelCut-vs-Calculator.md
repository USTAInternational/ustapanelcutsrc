# Первичный анализ: «Usta PanelCut» (Index.html) ↔ «Раскладка панелей» (репозиторий)

_Дата: 2026-07-07. Сравнение двух продуктов для расчёта, раскроя и сметы сэндвич-панелей и предложение по их слиянию._

> Примечание. Локальный путь `D:\Owncloud\2. AI first BIM LLC\13. IFC Audit` недоступен из облачной среды — анализ построен по двум фактически доступным артефактам: приложенному файлу `Index.html` и коду репозитория `nbaishev/sandwich-panels-calculator`.

---

## 1. Что это за два продукта

| | **Продукт A — «Usta PanelCut»** (`Index.html`) | **Продукт B — «Раскладка панелей»** (репозиторий) |
|---|---|---|
| Форма | Один автономный HTML-файл (~655 строк, чистый JS + SVG) | React 19 + TypeScript + Vite + Three.js, модульная архитектура |
| Запуск | Двойной клик, `file://`, без сервера/сборки, работает офлайн | `npm install && npm run dev`, сборка Vite |
| Единицы ядра | Метры (`GRID = 0.01`) | Миллиметры (площади в мм²) |
| Модель здания | Каркас по осям колонн L–A–B–C–D, 8 зон, треугольные фронтоны | Габариты (длина/ширина/высота), 4 фасада + скаты |
| Раскрой | Жадная укладка обеих ориентаций, подрезка по проёмам | Полосовой clipping полигонов, разрез по макс. длине, углы реза |
| Проёмы | Есть, вырезаются, идут в обрамление | Есть, с валидацией «выходит за фасад», вырезы в панелях |
| Визуализация | 2D SVG-чертёж по ЕСКД (оси, засечки 45°, размеры) | 3D-модель (Three.js) + 2D-развёртки + общая развёртка |
| Смета | Полная: материалы + СМР + транспорт + подписи + М.П. | Стоимость по 3 режимам площади + доборные + метизы |
| Экспорт | CSV, DXF (R12, cp1251), SVG, PDF (коммерческое предложение), печать | JSON, CSV, SVG, PDF |
| Коммерческая часть | Готовое КП: заказчик, менеджер, завод БИАСТ, маршрут 2ГИС/Google, сроки монтажа | Отсутствует (нет реквизитов, КП, подписей) |
| Тесты / типизация | Нет | 24 теста (Vitest) ✓, строгая типизация TS ✓ |
| Группировка марок | Нет (каждая панель отдельно) | Есть (`groupSimilarPanels`, канонизация полигона, зеркальность) |

**Статус проверки готовности (выполнено в этой сессии):**
- Продукт B — `npm run typecheck` проходит без ошибок, `vitest` — **24/24 теста зелёные**. Код собирается и функционирует.
- Продукт A — самодостаточный, открывается и считает в браузере без зависимостей.

## 2. Что работает и годно для презентации

### Продукт A — «Usta PanelCut» (готов показывать заказчику «как есть»)
1. **Коммерческое предложение под ключ.** PDF/печать с шапкой, реквизитами завода БИАСТ, менеджером, двумя блоками подписей и М.П. — это то, что можно сразу отдать клиенту.
2. **Полноценная смета** тремя разделами (материалы, СМР, транспорт) с редактируемыми ценами, итогами, сроком монтажа и расходом метизов.
3. **Чертёж по ЕСКД**: оси колонн с кружками, размерные линии с засечками 45°, полные размеры на каждой панели — выглядит «инженерно».
4. **Богатый экспорт**, включая **DXF** (которого нет в продукте B) — прямой мост в AutoCAD.
5. **Нулевой порог входа**: один файл, офлайн, маршрут доставки в 2ГИС/Google. Идеально для менеджера в поле.
6. **UX-мелочи**: подсказки `?` на каждом поле, сохранение/загрузка проекта в JSON, адаптивная вёрстка и print-стили.

### Продукт B — «Раскладка панелей» (сильная инженерно-техническая база)
1. **3D-модель здания** (Three.js: орбита, гизмо, рёбра) — самый эффектный элемент для презентации «вау».
2. **Корректная геометрия раскроя**: реальный clipping полигонов, разрез длинных полос с распределением по `calculateSplitLengths`, вычисление **углов реза** (`cutAngle`) для скатов и фронтонов.
3. **Группировка одинаковых марок** с канонизацией полигона и учётом зеркальности — это именно то, что нужно производству (ведомость по маркам, а не по каждому листу).
4. **Три режима расчёта площади/цены** (видимая / заготовка / номинал) и раздельные системы для стен и кровли (толщина, RAL, утеплитель, ширина).
5. **Инженерная строгость**: строгие типы, валидация проёмов и Zod-схема проекта, система предупреждений (узкая панель, превышение длины, доля отходов).
6. **Тесты и типобезопасность** — продукт можно развивать без страха регрессий.

**Вывод по презентабельности:** A — «продающий» продукт (КП, смета, ЕСКД, DXF), B — «производственный/инженерный» продукт (3D, корректный раскрой, марки, тесты). Для сильной презентации нужны оба лица.

## 3. Где требуется доработка

### Продукт A — «Usta PanelCut»
- **Нет разреза длинных панелей.** При длине > 12 м панель просто не укладывается — в продукте B это решено (`calculateSplitLengths`).
- **Нет группировки марок**: каждая панель — отдельная строка. Для производства нужна ведомость «марка × количество».
- **Модель геометрии проще**: жадная укладка по AABB, ориентация выбирается по минимуму срезки; нет истинных углов реза на фронтонах/скатах.
- **Нет 3D** — только 2D-схема.
- **Расстояние доставки вводится вручную** (км не считаются автоматически) — честное ограничение офлайн-файла, но узкое место.
- **Монолит без тестов**: один файл ~655 строк, невозможно покрыть тестами и тяжело поддерживать вдвоём.
- **Утеплитель/тип панели** не моделируются (в B — `insulation`, раздельные системы).

### Продукт B — «Раскладка панелей»
- **Нет коммерческой части**: ни реквизитов, ни КП, ни подписей/М.П., ни менеджера/завода — на выходе инженерный документ, а не предложение заказчику.
- **Цены по умолчанию = 0** (`defaultProject`): смета не заполнена, нужно вводить прайс руками; нет транспорта/логистики и сроков монтажа.
- **Нет DXF-экспорта** — критично для передачи в CAD.
- **Нет модели «по каркасу колонн»** (оси L–A–B–C–D, сечение колонны) — B считает только от габаритов; для реконструкции существующего каркаса это ограничение.
- **Требует сборки** (`npm`) — нельзя «просто открыть файл», менеджер в поле так не запустит.
- **Чертёж без явной ЕСКД-простановки осей/размеров** уровня продукта A (нужно сверить `SurfaceDrawing`/`CombinedUnfolding`).
- **README заявляет ограничения**: только прямоугольный план, симметричная двускатка; панели сверх макс. длины «не делятся автоматически» (расходится с наличием `calculateSplitLengths` — требует проверки/синхронизации документации).

## 4. Предлагаемое слияние

**Стратегия: React/TS-ядро продукта B как единая платформа + коммерческий слой и офлайн-режим из продукта A.** Продукт B — правильная архитектурная основа (типы, тесты, модульность, 3D, корректный раскрой). Продукт A даёт то, чего в B нет и что ближе всего к деньгам: КП, смету, ЕСКД, DXF, автономность.

### Что переносим из A в B
1. **Коммерческий модуль** (`src/commercial/`): реквизиты завода/менеджера, блок «Объект/Заказчик/Контакт», подписи + М.П., генерация PDF-**коммерческого предложения** (перенести шаблон из `exportPdf` продукта A).
2. **Полная смета**: разделы Материалы / СМР / Транспорт, редактируемый прайс, сроки монтажа, расход метизов — расширить существующий `calculateProject`/`Summary`.
3. **DXF-экспорт** (R12/POLYLINE, cp1251) — перенести `exportDxf` в `src/export/files.ts`.
4. **ЕСКД-простановка** (оси колонн, засечки 45°, размеры) — перенести логику `drawAxesAndDims`/`vdim` в `SurfaceDrawing`.
5. **Режим «по существующему каркасу»** (оси L–A–B–C–D, сечение колонны, треугольные фронтоны как зоны) — добавить как альтернативу габаритной модели.
6. **Логистика**: поле адреса + кнопки маршрута 2ГИС/Google, тариф сом/км.

### Что оставляем/усиливаем в B
- 3D, полосовой clipping, разрез длинных панелей, углы реза, группировка марок, три режима цены, валидация, тесты — это ядро.
- Русская локализация и терминология уже согласованы между продуктами.

### Что добавить сверху
- **Двойная сборка**: обычный SPA (`npm run dev`) **и** сборка «всё-в-одном-файле» (Vite `viteSingleFile`) — чтобы получить автономный `Index.html`, как у продукта A, но на новом ядре. Это закрывает главное преимущество A (офлайн, один файл) без потери архитектуры B.
- **Единая модель проекта** (расширить `ProjectInput`/Zod-схему полями коммерции, логистики и каркаса) + миграция `formatVersion`, чтобы старые JSON-проекты обоих продуктов читались.
- Регресс-тесты на смету и раскрой каркасной модели.

### Дорожная карта (черновик, по этапам)
1. **Этап 1 (быстрый эффект):** DXF-экспорт + коммерческий PDF + смета с транспортом в продукт B. → Получаем «продающую» версию инженерного продукта.
2. **Этап 2:** ЕСКД-оси/размеры на развёртках + сборка single-file. → Закрываем офлайн-сценарий и «инженерный вид».
3. **Этап 3:** режим «по каркасу колонн» и треугольные фронтоны. → Полный паритет геометрии с A.
4. **Этап 4:** единая схема проекта + миграции + тесты сметы/каркаса. → Один продукт вместо двух.

### Итоговое позиционирование
Один продукт — **React/TS-ядро с двумя лицами**: онлайн-SPA с 3D для офиса/производства и автономный single-file `Index.html` с КП, сметой, ЕСКД и DXF для менеджера в поле. Продукт A становится не отдельным приложением, а _режимом экспорта/сборки_ единой платформы B.
